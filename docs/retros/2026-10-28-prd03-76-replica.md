## What was built

- **Kind of code:** a replica builder, a refresh CLI (`node dist/mcp/refresh.js --watch`), an `openReplica` read-only opener, and tests. No migration, no new driver.
- **Pattern:** default-deny allowlist. A new file lists named columns per table; the replica is built by copying only those columns (with `account_last4` masked from `formatted_account`) using the existing sqlite3 5.x `Database#backup`, opened with `mode=ro&immutable=1` and `LIMIT_ATTACHED 0`. Sync detection reads the max finished `sync_runs` id from the live file, so there is no edit under `server/sync`.
- **Allowlist:** accounts, account_settings, bills, bill_payments, budgets, goals, goal_contributions, habit_verdicts, settings (rows where key is in `SETTING_KEYS`), sync_runs (started_at, finished_at, outcome), transactions, and `replica_meta`.

## What happened

- **Schema-reviewer:** allowlist matches the real schema. One gap: `transactions.balance_cents`, which `get_habits` overdrawn-day streaks need, is left out because Ruling 2's list is "exactly". Follow-up to file. The issue comment said four `SETTING_KEYS` rows; the code has five.
- **Test-guard:** every Done-when covered; 5 mutations all turned tests red. Two timing-flake notes: the real-time watch test uses a 5 s `waitFor`, and a loop asserts `reads > 10`.
- **Security-auditor:** no critical findings. EXECUTED against a WAL-mode live DB: each refresh left `.divvy-replica-copy-*-wal` and `-shm` files (about 288 pairs a day), the unscrubbed scratch copy was 0644 with no crash sweep, and the replica was 0644.
- **Reviewer:** EXECUTED: a quoted identifier (`"pragma_database_list"`) bypassed the refused-word check and returned the replica's absolute path. Low severity, since the SQL is only `staticSql` from source.
- **Fixes (5383c40):** quoted-identifier text is now kept for the check; `sealCopy` sets 0600 and `journal_mode=DELETE`; `-wal`/`-shm` are cleaned up; a dead-pid sweep removes orphaned scratch files; the replica is 0640. All auditor items fixed.

## What went wrong

1. **WAL side-file leak and open scratch copy (Missed-by: do).** The implementer's tests ran against a non-WAL fixture, so the leak only showed when the auditor used a WAL live DB. Production runs WAL under Litestream. Cost: a real disk and permission defect found a round late.
2. **Quoted identifiers bypassed the refused-word check (Missed-by: do).** The literal-stripping helper treated quoted identifiers like string literals and dropped their text. Found at review, not build.
3. **`transactions.balance_cents` left out (Missed-by: plan).** `get_habits` needs it, Ruling 2 says "exactly". A follow-up, not a fix in this fence.
4. **Issue comment said four setting keys, code has five.** Cosmetic, caught by schema-reviewer.

## Root causes

- **Test fixture did not match production (item 1).** The live DB in tests was not in WAL mode, so tests could not show behaviour that only WAL has. This is the one cause the record supports.
- **Helper conflated two token kinds (item 2).** Literals and identifiers were handled by one stripping routine. Beyond that, unclear.
- **Item 3:** a spec ambiguity between the "exactly" list and a tool's need; unclear who should have caught it earlier.

## What worked, keep it

- **Default-deny allowlist in a new file with named columns only.** The schema-reviewer could check it line by line against the real schema.
- **No new driver and no `server/sync` edit.** Existing sqlite3 features covered the need and the fence held.
- **Separate seats found different things.** Auditor found the file and permission leaks; reviewer found the identifier bypass; test-guard's 5 mutations all went red.
- **Commit points held:** build, #132 test and review fixes are three separate commits.
