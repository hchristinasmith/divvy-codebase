# Retro: #429 prd04 Ruling 9, one Claude API client with a kill switch, a daily token budget and usage logging

## Retro summary (for the PR body)

#429 adds the one place Divvy calls the Claude API: `server/agents/llm/client.ts` (the only SDK importer), `config.ts` (the only reader of the key and model id) and `guard.ts` (kill switch, daily token budget). Usage is logged per agent run.

Gear 4, no shift. Implementer on opus. `reviewer`, `test-guard` and `security-auditor` ran. No architect or researcher (keep-lanes-small); `schema-reviewer` not needed (no migration). Two commits: `a332423` build, `7975d93` review fixes. The design held up. Review found two real holes, both fixed.

## What was built

- **Kind of code:** a server-side API client wrapper with a guard layer, plus tests (including real-SDK tests with `fetch` replaced).
- **Pattern:** usage is summed per agent run and written once by `finishRun` (the #428 contract is one row per run). The budget is read fresh from `agent_runs` on every call, plus the run's own unlogged tokens, on the NZ calendar day. The kill switch is re-read from env on every call.
- **Fence:** `tokensSpentToday` reads `agent_runs` directly from `guard.ts` because `agent-runs.ts` belongs to another lane.

## What went wrong

1. **Unreadable usage let billed calls go uncounted.** A reply with `NaN` usage made `costMicroUsd` throw a raw `RangeError` after the call was sent, outside the try, so its tokens were never added and a caller that caught the error kept calling. Reviewer demonstrated 5 calls under a 100-token budget logging 0 tokens. Fixed in `7975d93` by stopping the run.
2. **The SDK reads env even with an explicit key.** Security-auditor and reviewer both found it honours `ANTHROPIC_BASE_URL` and `ANTHROPIC_LOG`, so the key could go to another host or into logs. Fixed by pinning `baseURL` and `logLevel: 'off'`, with a test using the real SDK and replaced `fetch`. `ANTHROPIC_CUSTOM_HEADERS` cannot be neutralised; this is documented, not fixed.
3. **Wrong review brief.** The conductor's brief said `git diff main`, but local `main` had advanced by 5 merged commits, so the diff showed unrelated deletions. Corrected mid-flight by message to all three seats; the brief now diffs against the branch base. Cost: a few minutes and some confused reading.
4. **Test-guard could not mutate.** The auto-mode classifier denied its mutation attempts (it is a read-only seat). The implementer and reviewer each ran mutation sets, so coverage was not lost, but test-guard's contribution was reading only.
5. **A Co-Authored-By trailer** was added by the conductor against the user's CLAUDE.md rule and amended out before push. Second time in two retros (#428 item 8).
6. **Truncated handoff.** The prompt arrived starting mid-sentence. The issue body carried everything, so no cost.
7. **Implementer departures,** all reasonable: prices held in a `Map` because `no-money-writes.test.ts` refused computed member access; `startModelRun` refuses non-category kinds; `complete` after `finishRun` throws.

## Not verified

- Docker build: docker is not installed here. `npm run build` passes.
- The kill switch is env, so in practice it takes effect on restart. A true runtime switch needs a file or a settings row.

## Root causes

- **A branch name used as a diff base (item 3).** Local `main` is not the branch base once other PRs merge. Nothing in the brief template gave the base commit.
- **Trusting an SDK's defaults (item 2).** An explicit `apiKey` looked like full configuration; the SDK still reads other env vars. Only reading the SDK source and testing the real SDK showed it.
- **A billed call's accounting could throw without stopping the run (item 1).** The accounting assumed usage is always readable. The safe default for unreadable usage on a billed call is to stop, not to count nothing.
- **Item 5:** the harness attribution reminder against `~/.claude/CLAUDE.md`, same cause as #428. Recurrence.

## What worked, keep it

- **Three review seats found two real holes** with demonstrations (mutations, real-SDK test), not opinions.
- **Pinning the host and log level with a real-SDK test** proves the pin, not just the option being passed.
- **The fence was respected:** the direct read in `guard.ts` was chosen over editing another lane's file, and named as a follow-up.
- **Single-owner modules** (`config.ts` for env, `client.ts` for the SDK) make the network path easy to audit and test.

## Follow-ups

1. Per-call usage write or a `tokensSpentToday` accessor in `server/agents/db/agent-runs.ts`. A crash before `finishRun` loses the run's tokens, and concurrent runs do not see each other.
2. `no-money-writes.test.ts` header still says Ruling 7 "agents call nothing over the network". It should name `llm/client.ts` as the one network path and ban `@anthropic-ai/sdk` elsewhere.
3. `contracts.ts` `AgentConfig` comment says env reading belongs to the runner; the CLAUDE.md Security list should add `ANTHROPIC_*`.
4. Cache token counting, if prompt caching is added.
