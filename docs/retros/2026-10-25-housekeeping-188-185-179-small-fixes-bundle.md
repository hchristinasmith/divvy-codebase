## What went wrong

1. **#188's test did not exercise the filter, and neither seat that wrote it saw that.** The regression test used `'not-a-timestamp'`. `julianday()` of that is NULL, and NULL sorts last under `DESC`, so the garbage row was already ranked last without the filter. The other test string, `'now'`, did exercise it, but only because the wall clock is later than the fixture base time; on a fixed clock before the fixture it would pass without the filter. The whole filter could be deleted and a test would still have to be read carefully to see which one failed. Test-guard found it by mutation; the `'2999-...Z'` case is the one that depends on neither the clock nor NULL ordering. This is the same defect the #169 retro recorded for the claim step's `'now'` test (its test-guard suggestion 6 was to make the `'now'` test independent of the wall clock; it was left optional), copied into the route along with the filter. Cost: one test-guard mutation and one added case; no bad code shipped.
2. **A stated reason that nobody had verified.** "run.ts must not import from a route" was written into a code comment and a commit message with the confidence of a rule. The reviewer corrected the comment in `a9e45ef`. The message of `09e31bb` stays wrong in history; the PR body says so. Cost: one review finding, plus a permanent wrong line in `git log`. A wrong reason matters here because the copy needs a follow-up (#206) and a reader taking "must not import" at face value would never file it.
3. **#185: an untested fallback and a comment that did not match the code.** The reviewer deleted the `statusCode` fallback and the suite stayed green. The comment claimed finalhandler's precedence for `status` and `statusCode`; the reviewer found the claim wrong and a9e45ef reworded it (the handler reads `statusCode` only when `status` is not an integer). Then test-guard found four more surviving mutations in the same function. Cost: two rounds of tests on one 20-line function (`a9e45ef`, `1d72c04`). The implementer's original tests covered the cases the issue listed, which is what the issue asked for; the function's own branches (precedence, integer checks, the 3xx boundary) were not in the issue and not tested.
4. **The listed `status: 404.5` case was a false friend.** It looked like it covered "non-integer status" but did not kill dropping the final `isInteger` check, because `status: 404.5` is already rejected by the first `Number.isInteger(err.status)` and falls through to `statusCode`, which is undefined. The check it was supposed to guard is only reachable through `statusCode`. A case named for a property does not prove the property; only the mutation showed it.
5. **The gear trigger fired on a comment.** The #179 implementer reported `shifted 1 -> 4` because `.env.example` is a `**/.env*` file, which sends it to `security-auditor`. The auditor ran and found only empty values (the file is a template, and the change was a comment plus one commented-out line). The shift is reported as written; the trigger fired on content that carries no risk. The seat that ran was not wasted, since it also reviewed the #185 handler. Third lane to report a trigger that fired on risk-free content (test-only exports in #165/#166 and #177/#173, now a comment in a template).
6. **W1 was a plan-stage miss.** The issue said a 4xx status should be answered, and listed five body-parser cases. It never asked what else reaches the handler with a status. `AkahuError` and `XeroClientError` can carry an upstream 401 or 429, which now answer the client and log nothing. The code is right against the issue text; the issue was written from the body-parser cases. The #177 retro named this same shape for the same handler (W2 there, which is what #185 was filed to fix).

## Root causes

- **Authors do not mutate their own tests** (`author-blind-spot-on-own-mutants`, recurrence; last counted as at least the fifth sighting in the #169 retro, so this is at least the sixth, and it shows up in both #188 and #185). The implementer wrote tests from the issue's examples; every gap (NULL ordering hiding the filter, the untested `statusCode` fallback, precedence, 3xx, the integer checks) was found by the reviewer or test-guard running a mutation.
- **The test named for a property did not test the property** (`proxy-check-passes-without-the-property`, second named occurrence; first in the #177 retro, where it was "the response does not leak" standing in for "the log does not leak"). Here: `'not-a-timestamp'` standing in for "the filter is needed", and `status: 404.5` standing in for "the last isInteger check matters". In both, the input looks like it covers the case, and only deleting the code shows it does not.
- **A reason stated as fact without a check** (`reason-unverified`, first occurrence). The wrong "must not import from a route" came from guessing why a fence exists. The record does not show any check of the import direction. Seat: do. Caught in review. Record only.
- **Spec written from the happy case** (`spec-from-happy-case`, recurrence of the #177 retro's W2, same handler). The fix was designed from body-parser's errors and not from the other things that call `next(err)` with a status. Seat: plan; `Missed-by: plan` on #203. No architect at gear 1-2 by design.
- **Gear trigger is blind to content** (`gear-trigger-blind-to-content`, third occurrence; first two named as "blind to test-only code"). The table matches on a path or a symbol, not on what changed or what the file can hold. Recorded, with the count, in "Recommended changes".
- **Copy because of a fence** (symptom of the lane model, not a lane mistake). The status route needed the claim filter and could not edit `run.ts`. Copying with a "change both together" comment and filing #206 is the correct move under the fence; the cost is that two copies now exist until #206 lands.

## Recommended changes

1. **A test for a filter or guard must fail when the filter is deleted, and the implementer says so (second occurrence of the proxy-check cause, so encode).** Add to the lane handoff and the boundary-input checklist: for each new guard, one test whose only difference from a passing run is the guard, shown red with the guard removed; an input that sorts or fails the same way without the guard (NULL under DESC, a value already rejected by an earlier check) does not count. Artifact: `docs/testing.md`, assertion rules, next to the boundary-input checklist the #169 retro added; plus the conductor's lane-handoff template. Single sentence, not a procedure.
2. **Make the `'now'` test clock-independent, or replace it with a fixed far-future string.** The test-guard suggestion from the #169 retro is now copied into a second file. Use `'2999-01-01T00:00:00Z'` style strings in both `server/sync/__tests__/run.test.ts` and `server/routes/__tests__/sync.test.ts`. Artifact: those two test files. Optional, tiny, can ride with #206.
3. **Comments that give a reason name the thing that was checked.** "Copied because run.ts is fenced to lane #155" is checkable; "must not import" was not. For a reviewer: when a comment says "must" or "cannot", ask what enforces it. Artifact: the reviewer agent's checklist. First occurrence; record only, do not encode yet.
4. **For an error-handler or fallback issue, list what else arrives there with a status** (upstream clients, `AkahuError`, `XeroClientError`). Second occurrence of the cause (first was the #177 retro's recommendation 3, which was marked optional). Now warranted. Artifact: the issue template used by the slicing session (check `.github/ISSUE_TEMPLATE/` first; if absent, the slicing session's template).
5. **Gear table: say that a comment-only or template-only change to a `**/.env*` file does not shift to gear 4, and that a symbol imported only by tests does not shift to 3.** Third occurrence of a trigger firing on risk-free content. Artifact: `~/.claude/CLAUDE.md`, "Gears" table, and via `pnpm import-workflow` the project's copy. This is a workflow-file change, so it owes a pre-test and a marker in `~/.claude/workflow-changes.md`: the count of reported shifts in PR bodies over the next 10 lanes that the conductor disputes, reported as count over denominator. Not done in this lane. Note the auditor's cheap run here is a reason to keep a rule, not a reason to drop it: the proposal narrows the trigger on content, it does not skip the seat for `/api` or `.env*` changes that touch values.
6. **Decide who owns the shared claim filter.** #206 shares it; until then each filter change needs both files. Artifact: #206 itself (a unit test that imports both and fails if they diverge would make "change both together" checkable). Optional.
