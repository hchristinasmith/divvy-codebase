## What was built

- **Kind of code:** a React app shell (sidebar, header, scope toggle, sync pill, phone tab bar), design tokens, self-hosted fonts, a route table with a stub per screen, and TanStack Query key helpers. Tests sit beside each piece.
- **Pattern:** one route table, `client/screens/routes.tsx`, drives the sidebar, the tab bar and the `Routes`. Each screen renders its own `ScreenHeader`, so later lanes edit only their own directory and never the shell or `App.tsx`. Scope is in-memory React context (`all` | `personal` | `strawb`, default `all`). The sync pill reads `GET /api/v1/sync/status` `lastSuccessAt` (the #27 contract) through `client/hooks/useSyncPill.ts`. Tokens are a Tailwind 4 `@theme` block in `client/styles/App.css`; Outfit, DM Sans and DM Mono come from `@fontsource` devDependencies, the Google Fonts `<link>` is gone and a viewport meta was added. `App` now renders inside the shell with Overview at `/`; the old pages stay at `/dashboard` and the rest until w5.
- **Why this shape:** the issue's "later waves only fill their own directory" claim has to be checkable. The fetch lives in `useSyncPill.ts` because `client/apis/apiClient.ts` was outside the fence.

## What went wrong

1. **A commit landed with lint red.** The gate was run as `... | tail`, so the pipe replaced the exit code with `tail`'s. Lint was failing on `promise/param-names` for `(r) => setTimeout(r)`. It was caught before push and amended. From then on the gate ran from a `gate.sh` with `set -euo pipefail`. Cost: an amend, and a gate line that read as a pass without proving it. This is the second retro in a row where the gate command hid an exit code (the barrel retro had `${PIPESTATUS[0]}` under zsh).
2. **A stash crossed between worktrees.** The stash stack is shared by every worktree of one repo. The reviewer subagent ran `git stash push` and `pop`, crossed another lane's stash, and staged ten `mcp/` files into this lane's index. The coordinator caught it. The files were backed up to the scratchpad, unstaged and deleted. Nothing under `mcp/` was ever committed. The standing rule now is: never `git stash` in a lane.
3. **Font packages were first installed as dependencies.** They were moved to devDependencies to match the Dockerfile prune.
4. **`new URL(..., import.meta.url)` threw in jsdom.** The config-reading tests were switched to the node environment.
5. **Headless Chrome has a minimum window width of about 500px,** which clipped the 390px screenshots. Switched to playwright-core with real viewports.
6. **`npm install --package-lock-only` after the rebase produced unrelated `oxide-wasm32-wasi` optional-dependency churn.** It was discarded.

## Root causes

- **Gate snippet is not exit-code-safe (recurrence).** Last time it was a bash-only `PIPESTATUS` under zsh; this time a `| tail` pipe. The names differ, the cause is the same: the lane writes its own gate command each time and nothing makes it fail loudly. Second occurrence in two consecutive retros, so a fix is now earned.
- **Shared git state is invisible from inside a worktree.** `git stash` looks local but the stack is repo-wide. No written rule against it existed in CLAUDE.md or, as far as the record shows, in the reviewer brief. This is a first occurrence, and it was contained by the coordinator, not by any check.
- **The plan did not state install type or test environment.** Devdep versus dep, and jsdom versus node for config-reading tests, were found by running into them. Small cost each, no deeper cause I can point at.
- **Cause of the rebase lockfile churn:** unclear. It happened on `--package-lock-only` and was discarded; I cannot say more from the record.

## What worked, keep it

- **Regression test committed green on the old `App` before the rewire** (6021644). The route move had a fixed reference.
- **One route table drives everything.** The "a screen issue never edits `App.tsx`" claim is checkable by a test on the table.
- **Executing the browser check instead of reasoning about it.** The 58/58 local-only request count and the 390px measurements are facts, not expectations, and they caught the clipped-viewport tooling problem early.
- **Mutation checks by test-guard.** They found a surviving mutation (minute tick masked by the refetch) and a redundant `end` prop that a green suite would never have shown.
- **Neutral state for every pill failure path,** so the pill never claims a sync time it does not have.
- **Building five tabs and not inventing an entry point,** per #33. Hannah's undecided choice stayed hers.
- **Reviewer caught a real time bug** (fresh reply aged against a stale tick) that the tests as first written did not.

## Recommended changes

1. **High leverage:** commit one exit-code-safe gate script and make it the only way the gate is run. Path: `scripts/gate.sh` with `set -euo pipefail` running `npx tsc --noEmit`, `npm run lint`, `npx vitest run` and printing each step's exit status. Reference it from the "Pre-commit checks" section of `CLAUDE.md`. Rule met: this is the second occurrence.
2. **Medium:** add a line to the "Worktrees and lanes" section of `CLAUDE.md`: never `git stash` in a lane, because the stash stack is shared across worktrees; use a WIP commit instead. First occurrence, so by the retro rule this could wait. It is cheap, the contamination reached the index, and the rule is already being applied in this lane, so it is written down here for the coordinator to decide. Subagent briefs (reviewer) should carry the same line.
3. **Optional:** in the brief for any dependency-adding issue, state "devDependencies" for build-time assets and "client tests that read config use `// @vitest-environment node`". No new artifact; put it in the issue text.

## Highest-leverage next step

Add `scripts/gate.sh` (with `set -euo pipefail`, one step per line, a printed exit status per step) and point the "Pre-commit checks" section of `CLAUDE.md` at it, so no lane writes its own gate pipe again.
