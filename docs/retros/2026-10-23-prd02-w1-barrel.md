# Retro: #43 prd02 w1, server routes mount through a barrel

Gear 3 as stamped; no shift. No migration, no file outside the code fence apart from this retro, and the new default exports were the issue's stated shape. Lane ran off the record (Baseline does not know this project yet), so there is no run id and nothing was posted.

## What was built

- **Kind of code:** an Express `Router` barrel plus six placeholder routers, with a supertest suite and a mount-table test.
- **Pattern:** `server/routes/index.ts` mounts accounts (`akahu.ts`), categories and transactions as before, plus overview, settings, budgets, bills, goals and habits. `server/server.ts` mounts it once with `server.use('/api/v1', routes)`, replacing three direct mounts. Each placeholder is its own file with a default router that answers 501 `{ error: 'Not implemented: <name>' }` through a path-less `router.use`, so every method and sub-path is covered. There is deliberately no catch-all: an unknown `/api/v1` path is still Express's 404.
- **Why this shape:** the point is that six later lanes each edit only their own file and never `server.ts` or the barrel.

## What happened

The architect plan came first. Commit f1d5963 pinned the existing routes and the unknown-path 404 and ran green against the old direct mounts. The accounts tests delete the `AKAHU_*` env vars so the proxy refuses with 500 `Missing Akahu credentials` and never reaches the network. Commit a2703cc then added the barrel, the placeholders and the mount-table tests. Those tests read Express 4 `_router.stack` and `layer.regexp` to assert that `server.ts` has exactly one router layer (the barrel) and that the barrel's layers match the expected names one-to-one.

Checks on the tests, all measured:

- The author ran 5 mutations, all red for the titled reason.
- The reviewer ran 11 mutations, all killed. It also probed 7 methods across 23 paths, and the old and new apps answered byte-identically.
- Test-guard ran 10 mutations, all killed.
- Reviews produced 0 findings and 0 fixes. The gate was green: tsc 0, lint 0, vitest 130/130 in 13 files.

## What went wrong

Not much. The one process slip was the gate command. It used bash's `${PIPESTATUS[0]}` under zsh, which printed an empty lint exit code, so the gate output did not show lint passing. The author re-ran lint to get a real exit status. The cost was one extra lint run, and a gate line that would have read as a pass without proving it.

## Known gaps left on purpose

- **The mount-table test cannot see a non-router handler mounted directly in `server.ts`** (for example `server.use('/api/v1/x', fn)`). An allowlist of `server.ts` layers would close that. It would also break the concurrent lane (#90-#92), which adds an SPA fallback to the same file. Left open.
- **The mount-table test depends on Express 4 internals.** It needs a rewrite on Express 5. A comment in the test says so.
- **The six placeholders are near-identical files.** A shared helper was rejected because it would sit outside the fence and each lane deletes its copy anyway.
- **`docs/retros/` is outside issue #43's declared fence.** It was created because the lane brief asked for a retro file.
- **`docs/audit-2026-10-23.md:29` lists API routes under `server/server.ts`, which is now indirect.** Left alone as a dated snapshot.

## Root causes

- **Gate command written for the wrong shell.** The lane's gate snippet assumed bash and ran in zsh. This is a tooling mismatch, not a decision.
- **The only real risk is outside this diff.** #90-#92 edits `server.ts` (removes `cors()`, adds an SPA fallback). If that fallback is a `get('*')` that does not exclude `/api`, the unknown-path 404 test goes red after rebase. That would be a true regression the test is built to catch, not a flaky test. Whoever rebases second has to treat it as one.

## What worked, keep it

- **Regression tests committed green on the old code before the change.** Moving the mounts then had a fixed reference, and the byte-identical probe confirmed no behaviour drift.
- **Env-stripping in the accounts tests.** It gets a deterministic refusal without network access or a mock.
- **Asserting the mount table both ways.** It checks that `server.ts` has only the barrel and that the barrel has exactly the expected layers. That is what makes the "later lanes never touch these files" claim checkable.
- **Mutation checks by three separate seats.** All killed, so the tests are not decoration.

## Recommended changes

1. **High leverage:** make the lane gate snippet shell-neutral. Use `cmd; echo "exit $?"` per step instead of `${PIPESTATUS[0]}`. It belongs in the lane handoff template or the gate runbook, not in this retro. Per the retro rule, encode it only if it recurs, since this is the first occurrence.
2. **At rebase time of #90-#92:** check that the SPA fallback excludes `/api`, and run `server/routes/__tests__/barrel.test.ts` first. No new artifact needed.

## Highest-leverage next step

When the second of #43 and #90-#92 rebases, run the barrel test before anything else and treat a red unknown-path 404 as a real regression to fix in the fallback, not in the test.
