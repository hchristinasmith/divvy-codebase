# Divvy audit — 2026-10-23

Audit of `divvy-codebase` (last commit 2025-07-08) against the product direction. Read-only; nothing was run (no tsc, lint, build or app), so "likely" items are from reading.

> Superseded by #9, #19, #129: the route is now `PATCH` with `{ category }`. The `PUT` rows below describe the code at the snapshot date.

## TL;DR

Early prototype. One real working path: an Express proxy to Akahu with a single hardcoded personal token, feeding the Dashboard. Auth0 is wired on the client only and gates nothing. The SQLite DB is seeded from a private file that is not in the repo, and nothing writes Akahu data into it. Almost nothing in the direction exists yet.

## 1. What exists today

**Stack** — React 18, Vite 5, Tailwind 4, react-router 7, TanStack Query 5, shadcn/Radix · Express 4, Knex 2, sqlite3 (+ unused pg) · TS 5, vitest 1 (no tests), ESLint 8.

| Path | What it actually is |
|---|---|

| `server/` | Live Express API + Knex migrations/seeds in `server/db/`. |
| `src/` | shadcn UI primitives + `lib/utils.ts`. `@` alias points here. Misleading name, not dead. |

| `data/` | Akahu category taxonomy (`rawCategories.js`, `cats.js`); `txnsCatSimp.js` all commented out. |

**Database** (`server/db/knexfile.js`) — SQLite in every env, prod path `/app/storage/prod.sqlite3`. README says Postgres; wrong.
Tables: `transactions` (Akahu shape, amount as float), `users` (email + password), `targets`, `wishlist_items`, `settings`, `user_challenges`. No accounts table, no category table. Seed `transactions.js` imports a gitignored `spending.js`, so seeding fails on a fresh clone.

**Auth** — Auth0 client-side only (`client/index.tsx`), redirect hardcoded to localhost:5173, no protected routes, server has no JWT check, `cors()` wide open. Akahu token is one global env var.

## 4. Decisions the direction forces

1. **Hosting** — container + volume (Fly/Railway/VPS, matches Dockerfile) · Heroku-style dyno + managed Postgres (matches Procfile) · home server/Mac mini over Tailscale (most private).
2. **Database** — stay SQLite (one process + volume) · move to Postgres · Postgres everywhere incl. tests.
3. **Where Claude runs** — server calls Claude API (key on server; works for background jobs + phone) · MCP server over the DB for Claude desktop (no key, only when app open) · both.
4. **Auth** — keep Auth0 + add server JWT verification · single-user secret / Tailscale-only · Cloudflare Access. Drop `users.password` either way.
5. **Akahu mode** — personal-app static token (now) · full OAuth with per-user encrypted tokens (needed if anyone else connects).
6. **Xero tokens** — encrypted DB column · secrets manager · Xero Custom Connection (client credentials, paid, one org). Strawb admin consent is a non-code blocker.
7. **Job runner** — in-process cron (dies with web) · separate worker · host scheduler hitting a protected endpoint.
8. **Notification channel** — email · web push (covers phone) · Slack/Telegram bot · in-app only.
9. **Email ingestion** — Gmail/Graph OAuth · forwarding inbox + webhook · IMAP polling. Parsing could be Claude (ties to 3).
10. **Business vs personal model** — one DB with an entity/owner dimension · separate schemas. Settle before tax work.
11. **`wish_web/` and the wishlist concept** — delete · separate repo · fold into pause-before-you-buy.
12. **Money as integer cents** — do before budgets/tax maths.

## 5. Suggested milestones

**M1 Make it run again + foundations** — rename package; fix README; `.env.example`; delete `wish_web/`, root knexfile, `mockTransactions.ts`, `useFruits.ts`, stray tailwind file; drop unused deps; tsc + lint green; fix migrate scripts, Dockerfile CMD, static path; seed from a committed fixture; reconcile PATCH/PUT contract; vitest config + smoke tests; settle decisions 1, 2, 4, 12; optional Express 5 / Knex 3 bump.

**M2 Real data, private server, always fresh** — Akahu sync into DB (accounts table, upsert, pending); 15–30 min scheduler; deploy to chosen host with persistent DB; server-side auth, close the open proxy; Transactions page on DB data with search + category edit; dashboard targets from DB.

**M3 Budgets, categories, tagging** — targets CRUD wired; need/want tag; subscription detection on real data; Claude categorisation + corrections table; notification channel + budget alerts.

**M4 Business side + combined view** — Xero OAuth + tokens; sync invoices/bills/bank txns/pay runs; side-by-side dashboard; salary linking; safe-to-spend with GST/PAYE/company tax; safe-to-spend-low alert.

**M5 Bills and email** — email invoice ingestion + parsing; match to Xero bills; due reminders + paid confirmations.

**M6 Goals, accountability, advisor** — goal discovery chat; pause-before-you-buy; weekly check-in; streaks (fill Challenges); advisor over real numbers (Claude desktop first, phone later).
